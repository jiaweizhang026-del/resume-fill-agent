# 履历助手：使用与运营说明

> 本文面向产品负责人和后续维护者。技术交接细节见项目根目录的 `HANDOFF.md`。

## 1. 产品是什么

履历助手是一个 Chrome 侧边栏扩展，帮助求职者在招聘、网申等表单页面中，根据自己上传或粘贴的履历自动完成输入、选择、点击与页面内滚动。

- 用户先在插件设置中保存自己的履历；履历保存在该用户浏览器的本地存储中。
- 用户在侧边栏用自然语言下达任务，例如“根据我的履历填写当前页面”。
- Agent 读取当前页面可操作字段，调用模型分步填写。
- 插件不会自动提交表单；提交、验证码、支付及敏感确认仍由用户自行完成。

## 2. 用户实际怎么使用

1. 在 Chrome 中安装并打开“履历助手 Agent”。
2. 进入设置，粘贴或导入自己的履历文本。
3. 从产品方获得一条 `mix_live_...` 产品 Key，填入“产品 API Key”。
4. 打开招聘或网申页面，打开侧边栏，输入“根据我的履历填写当前页面”。
5. 观察填写结果，人工检查后自行保存或提交页面。

用户无需、也不应填写 DeepSeek API Key、网关地址或模型名称。这些属于平台运维配置。

## 3. 系统如何工作

```text
用户的 Chrome 扩展
  ├─ 本地履历（chrome.storage.local）
  ├─ 产品 Key（mix_live_...）
  └─ 调用 https://api.jawi.top/v1/chat/completions
             │
Cloudflare Worker：resume-api
  ├─ 验证产品 Key 与剩余额度（D1）
  ├─ 成功调用预扣 1 个额度
  ├─ 调用 DeepSeek
  └─ 上游失败时退回本次额度
             │
DeepSeek 模型
```

Worker 和 D1 不保存用户履历、页面 DOM 或完整提示词；这些内容只在一次请求转发过程中使用。D1 保存的是产品 Key 的哈希、用户标签、额度和最近调用时间。

## 4. 销售与发卡流程

当前适合采用“一个客户/订单一把 Key”的方式。

1. 为客户创建一条唯一的产品 Key。
2. 仅通过私信、订单交付等私密渠道发送原始 `mix_live_...` Key；原始 Key 只展示一次，不能写进 Git、D1 或公开文档。
3. 在 D1 的 `product_keys` 表中，写入该 Key 的哈希、客户/订单标签和初始额度。
4. 用户将该 Key 填进插件即可使用。
5. 用户续费时，按其标签增加额度；违规或退款时可禁用该 Key。

建议标签使用可追溯但不敏感的格式，例如 `订单-20260908-001` 或 `微信昵称-尾号`，不要把身份证、完整手机号或履历内容写入标签。

### 常用 D1 运维 SQL

查看所有用户与余额：

```sql
SELECT
  label AS 用户,
  status AS 状态,
  credit_units AS 剩余额度,
  last_used_at AS 最近调用,
  expires_at AS 到期时间
FROM product_keys
ORDER BY last_used_at DESC;
```

给用户充值：

```sql
UPDATE product_keys
SET credit_units = credit_units + 100
WHERE label = '目标用户标签';
```

暂停或恢复：

```sql
UPDATE product_keys SET status = 'disabled' WHERE label = '目标用户标签';
UPDATE product_keys SET status = 'active' WHERE label = '目标用户标签';
```

额度按**模型调用次数**扣除，而不是按“用户点了一次填写”扣除：一次填写任务可能包含页面理解、填写、滚动和重试等多次模型调用。

## 5. 本地开发、更新与发布

工程目录：

```text
/Users/jawisworkspace/Documents/value thing/page-agent
```

修改扩展代码后：

```bash
cd "/Users/jawisworkspace/Documents/value thing/page-agent"
npm run typecheck
npm run build:ext
```

然后打开 `chrome://extensions`，点击本地扩展的刷新按钮。Chrome 本地加载目录为：

```text
packages/extension/.output/chrome-mv3
```

若改动了 Worker 的 `services/resume-api/worker.js`，还必须重新部署线上网关：

```bash
cd "/Users/jawisworkspace/Documents/value thing/page-agent/services/resume-api"
node --test worker.test.mjs
npx wrangler deploy --keep-vars
curl -sS https://api.jawi.top/health
```

`--keep-vars` 很重要：它会保留 Cloudflare 控制台已有的密钥变量，避免部署时覆盖它们。

## 6. Cloudflare 资源清单

| 资源 | 当前用途 |
| --- | --- |
| Worker `resume-api` | 产品 Key 鉴权、额度扣减、转发 DeepSeek 请求 |
| `api.jawi.top` | 插件调用的产品网关域名 |
| D1 `resume-product-keys` | 产品 Key 哈希、客户标签、余额与最近使用时间 |
| `DEEPSEEK_API_KEY` Secret | 仅保存在 Cloudflare 的上游模型 Key，绝不放进扩展或 GitHub |

## 9. 安全底线

- 不在聊天记录、截图、Git、文档或前端代码中保存任何真实密钥。
- 只在 Cloudflare Secret 保存服务方 DeepSeek Key。
- 数据库只保存产品 Key 的哈希，不保存原始 `mix_live_...` Key。
- 不自动提交招聘表单，不尝试绕过验证码、支付或网站安全机制。
- 处理真实简历时，按隐私政策向用户说明数据用途与第三方模型处理方式。
